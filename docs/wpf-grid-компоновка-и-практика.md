# WPF/XAML: изучаем контейнер Grid

**Учебный проект:** [RepoStudyPP](https://github.com/Huh-HAH-heh/RepoStudyPP)

**Цель:** научиться самостоятельно размещать элементы интерфейса в WPF с помощью контейнера `Grid`, понимать его свойства и уметь собирать разметку без случайных отступов и фиксированных координат.

## 1. Что такое контейнер компоновки

В XAML контейнер — это элемент, который может содержать другие элементы и управляет их расположением.

Например:

- `Grid` делит доступную область на строки и столбцы;
- `StackPanel` располагает элементы последовательно по вертикали или горизонтали;
- `DockPanel` прикрепляет элементы к сторонам;
- `WrapPanel` переносит элементы на следующую строку или колонку;
- `UniformGrid` создаёт сетку из ячеек одинакового размера.

Начинаем с `Grid`, потому что он уже используется в `MainWindow.xaml` проекта RepoStudyPP.

## 2. Базовая структура Grid

```xml
<Grid>
    <Grid.RowDefinitions>
        <RowDefinition Height="Auto"/>
        <RowDefinition Height="*"/>
    </Grid.RowDefinitions>

    <Grid.ColumnDefinitions>
        <ColumnDefinition Width="220"/>
        <ColumnDefinition Width="*"/>
    </Grid.ColumnDefinitions>

    <TextBlock Grid.Row="0" Grid.Column="0" Text="Заголовок"/>
    <Button Grid.Row="1" Grid.Column="1" Content="Открыть"/>
</Grid>
```

Контейнер сначала описывает сетку, а затем в него помещаются дочерние элементы.

Если у дочернего элемента не указаны `Grid.Row` и `Grid.Column`, он попадает в ячейку 0,0. Нумерация начинается с нуля.

Важно: `Grid.Row`, `Grid.Column`, `Grid.RowSpan` и `Grid.ColumnSpan` — присоединяемые свойства. Они указываются у дочернего элемента, но задаются системой компоновки Grid.

## 3. Размеры строк и столбцов

Это одна из главных частей Grid.

| Запись | Значение |
| --- | --- |
| `Height="120"` | Фиксированная высота 120 единиц WPF |
| `Height="Auto"` | Размер по содержимому |
| `Height="*"` | Всё доступное оставшееся пространство |
| `Height="2*"` | Доля в два раза больше, чем у `*` |
| `Width="220"` | Фиксированная ширина |
| `Width="Auto"` | Ширина по содержимому |
| `Width="*"` | Оставшаяся ширина |

Пример:

```xml
<Grid.ColumnDefinitions>
    <ColumnDefinition Width="200"/>
    <ColumnDefinition Width="2*"/>
    <ColumnDefinition Width="*"/>
</Grid.ColumnDefinitions>
```

После выделения 200 единиц первой колонке оставшееся место делится в соотношении 2:1 между второй и третьей колонками.

`*` не означает пиксели. Это пропорциональная доля оставшегося места.

### Минимальные и максимальные размеры

У строки или столбца можно ограничить размер:

```xml
<RowDefinition Height="*" MinHeight="80" MaxHeight="300"/>
<ColumnDefinition Width="2*" MinWidth="180"/>
```

Это полезно, чтобы панель не становилась слишком маленькой или слишком большой.

## 4. Размещение дочерних элементов

| Свойство | Назначение |
| --- | --- |
| `Grid.Row` | Номер строки |
| `Grid.Column` | Номер столбца |
| `Grid.RowSpan` | Сколько строк занимает элемент |
| `Grid.ColumnSpan` | Сколько столбцов занимает элемент |

Пример объединения ячеек:

```xml
<TextBlock Grid.Row="0"
           Grid.Column="0"
           Grid.ColumnSpan="2"
           Text="Общий заголовок"/>
```

Элемент занимает две колонки, начиная с нулевой.

## 5. Свойства самого Grid и свойства его детей

Не путай настройки контейнера с настройками размещаемых элементов.

### Настройки Grid

| Свойство | Для чего нужно |
| --- | --- |
| `RowDefinitions` | Описание строк |
| `ColumnDefinitions` | Описание столбцов |
| `ShowGridLines` | Временный показ границ ячеек при отладке |
| `Background` | Фон области контейнера |
| `Margin` | Внешний отступ всего Grid |
| `ClipToBounds` | Обрезать содержимое за границами контейнера |

Пример отладки:

```xml
<Grid ShowGridLines="True">
    ...
</Grid>
```

После настройки сетки `ShowGridLines` обычно отключают.

### Настройки дочерних элементов

| Свойство | Для чего нужно |
| --- | --- |
| `Margin` | Внешние отступы элемента |
| `Padding` | Внутренние отступы элемента, если он их поддерживает |
| `HorizontalAlignment` | Выравнивание по горизонтали |
| `VerticalAlignment` | Выравнивание по вертикали |
| `Width`, `Height` | Размер элемента |

Например:

```xml
<Button Content="Войти"
        Margin="8"
        HorizontalAlignment="Right"
        VerticalAlignment="Center"/>
```

`Margin` не резервирует ячейку и не меняет сетку. Он добавляет отступ вокруг дочернего элемента.

## 6. Важные правила компоновки

1. Не задавай каждому элементу фиксированные координаты: для этого Grid не предназначен.
2. Для шапок и строк с текстом часто используй `Auto`.
3. Для основной рабочей области обычно подходит `*`.
4. Для боковой панели можно задать фиксированную ширину или ограничить её через `MinWidth` и `MaxWidth`.
5. Не вкладывай Grid в Grid без необходимости: сначала проверь, можно ли описать сетку одним контейнером.
6. Если двум элементам нужно занимать одну ячейку, они накладываются друг на друга. Порядок объявления влияет на порядок отрисовки.
7. Вложенные контейнеры допустимы: например, внутри одной ячейки Grid может находиться StackPanel или другой Grid.

## 7. Задание №1 — форма авторизации

**Задача:** сверстать форму входа с помощью одного Grid.

Требования:

- заголовок «Вход в систему»;
- подписи «Логин» и «Пароль»;
- два поля ввода;
- кнопка «Войти»;
- кнопка «Регистрация»;
- место для сообщения об ошибке.

Условия:

- минимум 4 строки и 2 столбца;
- заголовок должен занимать обе колонки;
- подписи и поля должны быть выровнены;
- кнопки находятся в одной строке;
- основная ширина формы не должна зависеть от фиксированных координат;
- при изменении ширины окна поля должны расширяться.

**Что нужно продемонстрировать:**

- `Auto`, `*` и фиксированный размер;
- `Grid.Row`, `Grid.Column`, `ColumnSpan`;
- `Margin` и выравнивание.

Не добавляй обработчик авторизации: сейчас изучаем исключительно компоновку.

## 8. Задание №2 — окно приюта

**Задача:** спроектировать макет основного окна приложения.

Макет должен включать:

- верхнюю шапку с названием и аккаунтом;
- левую боковую панель навигации;
- центральную рабочую область;
- нижнюю строку состояния.

Требования:

- шапка занимает всю ширину;
- боковая панель имеет ограниченную ширину;
- рабочая область получает всё оставшееся место;
- строка состояния находится снизу;
- центральная область должна расширяться при растягивании окна;
- внутри центральной области разместить заголовок и две соседние карточки.

Разрешается использовать вложенный Grid для центральной области.

**Что нужно продемонстрировать:**

- несколько строк и столбцов;
- пропорции `*` и `2*`;
- `RowSpan` или `ColumnSpan`;
- вложенный контейнер;
- ограничения размеров;
- адаптацию при изменении ширины и высоты окна.

## 9. Порядок выполнения

Для каждого задания работаем одинаково:

1. Нарисуй схему строк и столбцов на бумаге.
2. Определи, какие размеры будут `Auto`, фиксированными и звёздочными.
3. Создай пустой Grid и опиши его строки и столбцы.
4. Расставь элементы через `Grid.Row` и `Grid.Column`.
5. Временно включи `ShowGridLines` и проверь разметку.
6. Измени размеры окна и исправь проблемы.
7. Отключи отладочные линии и проверь итоговый макет.

## 10. Самопроверка

После заданий ты должен уметь объяснить:

- почему `*` отличается от `Auto`;
- как Grid делит оставшееся место;
- почему дочерний элемент без координат оказывается в первой ячейке;
- чем `Margin` отличается от `Padding`;
- как растянуть элемент на две колонки;
- что произойдёт, если несколько детей поместить в одну ячейку;
- какие свойства относятся к Grid, а какие — к дочернему элементу.

Следующий контейнер после Grid — `StackPanel`. Его будем изучать отдельно и сравним, в каких случаях он проще и удобнее.
