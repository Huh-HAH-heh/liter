# Практическая работа №5 — переходы между окнами WPF

**Учебный проект:** [RepoStudyPP](https://github.com/Huh-HAH-heh/RepoStudyPP) — практическая работа №4 «Система учёта животных в приюте».

**Цель:** научиться проводить изменение интерфейса через события, создавать отдельные окна WPF, передавать данные через конструктор и сохранять состояние авторизованного пользователя между окнами.

## 1. Что уже есть в проекте

Перед изменениями важно зафиксировать исходную архитектуру:

- `MainWindow.xaml` содержит главную страницу, приют, авторизацию, регистрацию, заявки, ветеринарию и отчёт.
- `MainWindow.xaml.cs` хранит обработчики кнопок и переключает внутренние разделы методом `ShowPage(Grid page)`.
- `Models/ShelterData.cs` содержит модель `User` и общий список `UserStore.Users`.
- Вход уже проверяет логин и пароль через `FirstOrDefault`.
- Текущий пользователь хранится в поле `_currentUser` окна `MainWindow`.

Ключевой момент: сейчас `HomePage`, `ShelterPage`, `LoginPage` и остальные — это не окна. Это элементы `Grid`, которые показываются и скрываются внутри одного окна. Практическая №5 требует освоить другой механизм: создать отдельный экземпляр класса, унаследованного от `Window`.

## 2. Как работает переход между окнами

Цепочка событий в WPF выглядит так:

1. В XAML у кнопки указан обработчик, например `Click="OpenShelter_Click"`.
2. Пользователь нажимает кнопку.
3. WPF вызывает соответствующий метод C#.
4. Обработчик получает нужные значения из элементов управления.
5. Создаёт объект нового окна и передаёт значения в его конструктор.
6. Вызывает `Show()` или `ShowDialog()`.
7. Новое окно выполняет `InitializeComponent()`, после чего его элементы доступны из C#.

Минимальная схема:

```csharp
private void OpenWindow_Click(object sender, RoutedEventArgs e)
{
    var window = new ShelterWindow("Nerd", "Nerd");
    window.Show();
    this.Close();
}
```

Здесь `new ShelterWindow(...)` создаёт объект, `Show()` показывает его, а `Close()` закрывает текущее окно. Это три разных действия.

## 3. Передача параметров через конструктор

Если вызывающий код передаёт два аргумента:

```csharp
new ShelterWindow(login, password);
```

то у нового окна должен существовать конструктор с двумя строковыми параметрами:

```csharp
public partial class ShelterWindow : Window
{
    public ShelterWindow(string login, string password)
    {
        InitializeComponent();

        UserInfoText.Text = $"Логин: {login} | Пароль: {password}";
    }
}
```

Соответствие здесь строгое:

| Передаём | Принимаем |
| --- | --- |
| `login` типа `string` | `string login` |
| `password` типа `string` | `string password` |

Порядок и типы аргументов должны совпадать. `InitializeComponent()` нужен до обращения к `UserInfoText`: именно он загружает XAML и связывает имена элементов с полями класса.

> Важно: показ пароля на экране требуется только условиями этой учебной работы. В реальном приложении пароль нельзя отображать и хранить в открытом виде.

## 4. Что нужно изменить в проекте

### Этап A. Авторизация

В текущем проекте уже есть коллекция:

```csharp
UserStore.Users
```

И поиск пользователя:

```csharp
var user = UserStore.Users.FirstOrDefault(item =>
    item.Login.Equals(login, StringComparison.OrdinalIgnoreCase) &&
    item.Password == password);
```

Для задания нужно разделить две проверки:

- пустой логин или пароль — показать сообщение о незаполненных полях;
- заполненные значения не совпали с записью в списке — показать сообщение о неверном логине или пароле.

Не нужно создавать новый массив пользователей: существующий `UserStore.Users` уже выполняет роль списка эталонных учётных записей.

### Этап B. Состояние пользователя

Сейчас авторизованный пользователь находится в поле `_currentUser` конкретного `MainWindow`. Когда создаётся новое окно, оно не получает это поле автоматически.

Нужно выбрать явный способ передачи состояния:

- передавать объект `User` в конструктор следующего окна;
- либо создать общий объект сессии приложения.

Для учебной работы предпочтительнее сначала передать объект `User` напрямую: так хорошо видны источник данных, аргумент конструктора и место, где новый экран получает пользователя. Логин и пароль не нужно повторно искать после успешного входа.

### Этап C. Окна и кнопка «Назад»

Для каждого нового окна нужно определить:

- кто его открывает;
- какие данные передаются конструктору;
- какое действие выполняется по кнопке «Назад»;
- должно ли предыдущее окно оставаться открытым или закрываться.

Не следует бездумно создавать новое `MainWindow` при каждом возврате: это создаёт несколько независимых экземпляров главного окна. Нужно заранее выбрать единый сценарий владения окнами.

### Этап D. Проверка сценария

Проверять нужно не только запуск, но и последовательность действий:

1. Открыть приложение.
2. Попробовать войти с пустыми полями.
3. Ввести неверные данные.
4. Войти с существующей учётной записью.
5. Проверить, что данные пользователя отображаются в новом окне.
6. Перейти дальше и проверить передачу тех же данных.
7. Вернуться назад.
8. Убедиться, что данные приюта и роль пользователя не потерялись.

## 5. Как будем разбирать изменения

Работа идёт небольшими этапами. Для каждого этапа фиксируем:

1. **Задачу** — что должно измениться для пользователя.
2. **Точки входа** — какие XAML-элементы и обработчики участвуют.
3. **Поток данных** — откуда берётся значение, куда передаётся и где используется.
4. **Изменения файлов** — зачем нужен каждый изменяемый файл.
5. **Результат** — что должно заработать и как это проверить.

Главная цель — не просто получить работающие окна, а научиться самостоятельно прослеживать цепочку `XAML → событие → обработчик C# → конструктор окна → отображение данных`.
